banco.sqlSQL
CREATE TABLE livro_autores (
  codigo_livro varchar(10) NOT NULL,
  id_autor int NOT NULL,
  PRIMARY KEY (codigo_livro, id_autor),
  FOREIGN KEY (codigo_livro) REFERENCES livros(codigo_livro) ON DELETE CASCADE,

);

A chave composta impede o mesmo par livro–autor duas vezes. O INSERT IGNORE do formulário também ignora repetição.

A relação muitos-para-muitos é um grafo bipartido: livros de um lado, autores do outro, arestas = vínculos. A tabela de junção é a lista de arestas.

Busca e acervo

Form2.cs · Form3.Designer.cs

A busca do acervo combina junções, LIKE '%termo%', agregação de autores e uma subconsulta para saber quem está com o livro. A tela de empréstimos pagina com LIMIT/OFFSET.

Form2.cs · AplicarFiltroEBuscaSQL
WHERE UPPER(e.status) NOT IN ('CONCLUIDO','CONCLUÍDO')
  AND (e.excluido = 0 OR e.excluido IS NULL)
  AND (l.titulo LIKE @busca OR a.nome_guerra LIKE @busca ...)
ORDER BY e.id DESC
LIMIT @offset, @limite;

Confirmado: a contagem e a página são duas consultas; o filtro textual usa curinga nas duas pontas.

Com LIKE '%termo%' não há como usar o índice B-tree para localizar o início: o banco tende a varrer. A paginação com OFFSET também percorre e descarta.

varredura n→filtro→k linhas→página

Modelo didático: custo Θ(n) no filtro, mais o custo de materializar k resultados.

No código: GROUP_CONCAT dos autores e subconsulta com ORDER BY e.id DESC LIMIT 1 para o empréstimo ativo. (Form3.Designer.cs)

SELECT COALESCE(permite_emprestimo,1) FROM livros WHERE codigo_livro=@id;
SELECT COUNT(*) FROM emprestimos

São duas consultas e uma conexão por verificação. No menu com vários candidatos, cada candidato dispara o par.

Máquina de estados didática: Pendente → (data passou) Atrasado → (devolução) Concluído. O formulário grava o status; a data é a regra.
